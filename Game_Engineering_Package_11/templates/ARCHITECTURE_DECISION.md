# Architecture decision record

ID / date / status / linked proposal revision: [enter]

## Context
State the measured or specified constraint and the evidence that establishes it.

## Alternatives
Compare at least two credible alternatives with the same system boundary. Include correctness, latency, power, area/cost, complexity and maintenance where relevant.

## Decision and consequences
Name the selected option, rejected alternatives, accepted risks, assumptions and reversibility. A negative result may justify keeping the baseline.

## Validation and revisit trigger
Record tests/measurements, actual result, unresolved discrepancy and the observable condition that should reopen the decision.
